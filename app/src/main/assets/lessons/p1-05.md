# Training a tiny GPT

## The idea

Training chooses the parameters so that the model gives high probability to the true next token across the training text. The loss is cross-entropy: at each position take the negative log of the probability given to the correct token, then average over positions. This is the same NLL you met in the first lesson.

Worked example. If the correct next character has probability 0.5, its loss is -ln(0.5) = 0.69. If the probability is 0.1, the loss is 2.30. A model that is uniform over 65 characters pays ln(65) = 4.17 at every position. A freshly initialized model has small random weights, so its outputs are close to zero, and its loss starts near ln(vocab). Training should push the loss well below that.

Backpropagation computes the gradient of the loss with respect to every parameter, by applying the chain rule backwards through the network. `tinygpt.py` does this by hand, so each layer's backward pass mirrors its forward pass. Adam then uses the gradients to update each parameter. It keeps a running average of the gradient and of its square, and it scales each step by the size of that second average. The learning rate `LR` sets the overall step size.

Train and validation loss answer different questions. The training loss is measured on the data the model learns from. The validation loss is measured on the 10 percent held out. While both fall, the model is learning patterns that generalize. If training loss keeps falling while validation loss rises, the model is memorizing the training text. This is overfitting.

## How it works

Each step of the training loop does the following:

1. Sample `BATCH` random windows of length `BLOCK` from the training split. Targets are the inputs shifted by one character, so every position predicts the next one.
2. Run the forward pass to get logits and the loss.
3. Run the backward pass to get gradients for all parameters.
4. Apply an Adam step in place. The global gradient norm is clipped to 1.0 first.
5. Every 10 steps, record the training loss. Every `EVAL_EVERY` steps, estimate the validation loss over several batches.

The three lines that matter are:

```python
x, y = get_batch(train, BLOCK, BATCH, rng)
_, loss = model.forward(x, y)
opt.step(model.params, model.backward())
```

## In the lab

`lab04_train_gpt.py` trains `TinyGPT` on the bundled corpus. Its constants are `STEPS=1500`, `BATCH=16`, `BLOCK=32`, `N_LAYER=2`, `N_HEAD=2`, `D_MODEL=64`, `LR=3e-3` and `EVAL_EVERY=100`. It uses a 90/10 train and validation split, sends the loss curves to the chart, prints a 200-character sample at the end, and saves the model to the work folder. Pressing Stop saves the model before the run ends.

Try these:

1. Set `STEPS` to 300 and run. Then run with 1500. Compare the final validation loss, and describe the gap between the two curves.
2. Change `LR` to 1e-2, then to 1e-3. Which setting reaches a given loss in fewer steps, and which looks too slow to be useful?
3. Change `D_MODEL` to 32, then to 128. `D_MODEL` must divide evenly by `N_HEAD`. Does the final loss change, and how long does training take?
