# QLoRA fine-tuning

## The idea

QLoRA combines two ideas. The base model's weights are stored in 4 bits, which cuts their memory to roughly a quarter of 16-bit storage. On top of this frozen, quantized base, LoRA adapters are trained. The base model is only read during training, and the adapters are the only trainable part. The result is fine-tuning on a GPU that could not hold the full-precision model with its training state.

Worked example. A model with 3 billion parameters stores its weights in 16-bit floats, which take 3e9 x 2 bytes = 6 GB. In 4 bits the same weights take 3e9 x 0.5 bytes = 1.5 GB. Now add a LoRA adapter for one matrix of width 2,048 with rank 8. It has 2 x 2,048 x 8 = 32,768 trainable numbers, about 64 KB when stored in 16 bits. Only that small part needs gradients and optimizer state.

## How it works

1. Load the base model with 4-bit quantization. The `BitsAndBytesConfig` object sets this.
2. Wrap the model with LoRA adapters on the chosen linear layers, using `LoraConfig` and `get_peft_model`.
3. Print the trainable parameters. Only a small fraction of the model should be trainable.
4. Format each training example with the chat template, so the model sees the structure it was tuned on.
5. Compute the loss on the answer tokens and update only the adapters. During each matrix multiply, the 4-bit weights are converted back to a higher precision.
6. Save the adapter, which is a small file, rather than the whole model.

`lora_alpha` scales the adapter output by alpha divided by r. This is one extra knob beyond the plain `W + B·A` form in the previous lesson.

## Steps

1. Open a Colab notebook and choose a GPU runtime.
2. Install the libraries with `pip install transformers peft bitsandbytes accelerate datasets`.
3. Set `MODEL_ID` to a small instruct model of roughly 1 to 4 billion parameters. Check the model hub for current options and licences.
4. Load the model and tokenizer with the 4-bit configuration, as in the code below.
5. Print the model to find the names of its linear layers. Replace the placeholder in `target_modules` with those names.
6. Call `print_trainable_parameters` and confirm that the adapter is a small share of the total.
7. Prepare a small set of question and answer pairs, formatted with `apply_chat_template`.
8. Train for a few hundred steps with a standard loop or the `Trainer` from `transformers`, and watch the loss fall.
9. Save the adapter with `save_pretrained` to its own folder, and note its size.

```python
# Starting sketch. Check current docs for exact APIs.
import torch
from transformers import (
    AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig)
from peft import LoraConfig, get_peft_model

MODEL_ID = "your-chosen-small-model"  # check the licence

bnb = BitsAndBytesConfig(load_in_4bit=True)
tok = AutoTokenizer.from_pretrained(MODEL_ID)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID, quantization_config=bnb, device_map="auto")

cfg = LoraConfig(r=8, lora_alpha=16, lora_dropout=0.05,
                 target_modules=["your_layer_names"],
                 task_type="CAUSAL_LM")
model = get_peft_model(model, cfg)
model.print_trainable_parameters()
```

Library APIs change over time, so check the current `transformers`, `peft` and `bitsandbytes` documentation before you run this.
