# A real RAG pipeline

## The idea

The previous lesson used word counts. A real pipeline uses a learned embedding model, a small neural network that maps a chunk of text to a vector, so that texts with similar meaning land close together. Retrieval compares the question's vector with each chunk's vector by cosine similarity. A generator model, chosen in the first lesson of this phase, then answers from the top chunks.

Worked example of chunking. A 1,000-word document is cut into chunks of 200 words with 40 words of overlap. Each new chunk starts 200 - 40 = 160 words after the previous one. The chunk starts are 0, 160, 320, 480, 640 and 800, which makes 6 chunks. The last chunk covers words 800 to 1,000. The overlap means a sentence that crosses a boundary sits whole inside at least one chunk.

## How it works

1. Load each document as plain text.
2. Split each document into chunks of `CHUNK_WORDS` words, with an overlap.
3. Embed every chunk with the embedding model, and normalize the vectors to length 1.
4. Embed the question in the same way.
5. Score each chunk. For normalized vectors, the dot product is the cosine similarity. Keep the top k chunks.
6. Build the prompt. Give the model a short instruction, the chunks labelled [1], [2] and so on, and the question. Ask it to answer only from the context, and to say so if the context does not contain the answer.
7. Generate the answer and print it with the numbers of the chunks it used.

## Steps

1. Open a Colab notebook with a GPU runtime. Install the libraries with `pip install sentence-transformers transformers`.
2. Put a few of your own text files into the notebook, such as notes or a manual. Keep them small to start.
3. Write the chunking function with `CHUNK_WORDS` and an overlap. Print the number of chunks and check two of them by eye.
4. Embed the chunks with the sketch above and run one question. Print the top chunks and their scores.
5. Build the prompt, generate with the model from the first lesson of this phase, and check that the answer cites the chunks it used.
6. Ask a question that the documents do not answer, and check that the model says so.

Steps 3 to 5 start from this sketch. It assumes `chunks` is a list of strings you have already made.

```python
# Starting sketch. Check current docs for exact APIs.
from sentence_transformers import SentenceTransformer
import numpy as np

EMBED_ID = "your-chosen-embedding-model"  # check licence
embedder = SentenceTransformer(EMBED_ID)

chunks = ["first chunk text", "second chunk text"]
C = embedder.encode(chunks, normalize_embeddings=True)
q = embedder.encode(["my question"],
    normalize_embeddings=True)[0]
scores = C @ q
top = np.argsort(scores)[::-1][:3]
```

Library APIs change over time, so check the current `sentence-transformers` and `transformers` documentation before you rely on these calls.
