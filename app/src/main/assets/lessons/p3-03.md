# Quantization

## The idea

Quantization maps floating-point weights to a small set of integers, and keeps one float scale to convert them back. A weight stored as float32 takes 4 bytes. An int8 weight takes 1 byte and an int4 weight takes half a byte. Smaller weights need less memory and load faster on a phone, at the cost of rounding error.

Worked example with symmetric 8-bit quantization of the weights [0.5, -1.0, 0.3]. The largest magnitude is 1.0. For signed 8 bits we use integers from -127 to 127, so the scale is 1.0 / 127 = 0.007874. To quantize 0.3, compute 0.3 / 0.007874 = 38.1, which rounds to q = 38. To dequantize, compute 38 x 0.007874 = 0.2992. The error is 0.3 - 0.2992 = 0.0008.

Now the same weight at 4 bits. Symmetric 4-bit uses integers from -7 to 7, so the scale is 1.0 / 7 = 0.142857. Then 0.3 / 0.142857 = 2.1, which rounds to 2. Dequantized, that is 2 x 0.142857 = 0.2857, with an error of 0.0143. That is about 18 times the 8-bit error. Halving the storage again costs real accuracy.

## How it works

For one weight tensor:

1. Compute the scale. Take the largest absolute value and divide it by the largest integer for the bit width: 127 for 8 bits, 7 for 4 bits.
2. Quantize each weight: q = round(w / scale), clipped to the symmetric integer range.
3. Store the integers and the scale.
4. Dequantize when you need the values: `w_hat` = q x scale.
5. Measure. The size is the number of values times the bits per value. The error can be the reconstruction error of the matrix, or the validation loss of the whole model with dequantized weights.

The quantize step is short:

```python
def quantize(w, bits):
    qmax = 2 ** (bits - 1) - 1  # 127 or 7
    scale = np.abs(w).max() / qmax
    q = np.clip(np.round(w / scale), -qmax, qmax)
    return q.astype(np.int8), scale
```

A single scale for the whole tensor is called per-tensor. One large outlier then sets the scale for every weight. In the example above, adding a weight of 10.0 makes the scale 10.0 / 127 = 0.0787, and the weight 0.3 now quantizes to 4 x 0.0787 = 0.315. Its error grows from 0.0008 to 0.015. Per-channel or per-group scales avoid this, because each row or group gets its own scale.
