# Self-attention

## The idea

In a language model, each token needs information from the tokens before it. Attention lets each token look back and decide how much weight to give each earlier token. Every token produces three vectors. The query says what the token is looking for. The key says what the token contains. The value is what gets passed on. A token's query is compared with the keys of the tokens it may see. The scores become weights, and the output is the weighted sum of the values.

Worked example with 2-dimensional vectors. The query of the current token is q = [1, 0]. The keys of three visible tokens are k0 = [1, 0], k1 = [0, 1] and k2 = [1, 1]. The dot products are q.k0 = 1, q.k1 = 0 and q.k2 = 1. Divide by the square root of `d_head` = 2, which is 1.414, to get the scores 0.707, 0 and 0.707. Exponentials are 2.028, 1 and 2.028, with sum 5.056. The weights are 0.401, 0.198 and 0.401, which sum to 1. The output is 0.401 v0 + 0.198 v1 + 0.401 v2, dominated by the tokens whose keys matched the query.

## How it works

For one head, with input X of shape (T, `d_model`):

1. Project: Q = X Wq, K = X Wk, V = X Wv. Each has shape (T, `d_head`).
2. Score: S = Q K^T / sqrt(`d_head`). Entry S[i, j] says how much token i wants token j.
3. Mask: set S[i, j] to minus infinity for every j greater than i, so no token sees the future.
4. Softmax each row: A = softmax(S) row by row. Each row sums to 1, and masked entries become 0.
5. Output: O = A V. Each token's output is a weighted sum of the value vectors of the tokens up to and including itself.

Why divide by the square root of `d_head`? For random vectors, the variance of a dot product grows with the vector length. Without the division, large scores push the softmax into nearly one-hot outputs, where gradients are tiny. Dividing keeps the spread of scores roughly constant as `d_head` grows. The core is four lines:

```python
scores = q @ k.T / np.sqrt(d_head)
scores = np.where(mask, -np.inf, scores)  # mask: j > i
w = softmax(scores, axis=-1)
out = w @ v
```

A multi-head layer runs several such heads on slices of width `d_head` = `d_model` // `n_head` and concatenates the results.
