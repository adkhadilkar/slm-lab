# LoRA: low-rank adapters

## The idea

Fine-tuning every weight of a model is expensive. Gradients and optimizer state take memory for every parameter. LoRA (low-rank adaptation) keeps the pretrained matrix `W` frozen and learns a change to it that has low rank. The adapted layer computes `W + B·A`, where `A` has shape (r, d) and `B` has shape (d, r). The rank `r` is small compared with `d`, so the change has far fewer numbers to learn.

Worked example. Take a square matrix with d = 64. Full fine-tuning trains d x d = 64 x 64 = 4,096 numbers. LoRA with rank r = 4 trains `A`, which has 4 x 64 = 256 numbers, and `B`, which has 64 x 4 = 256 numbers. The total is 512, which equals 2 x d x r. That is 512 / 4,096 = 1/8 of the full count.

Why start `B` at zero? If `B` is zero, then `B·A` is zero, and the model starts exactly at its pretrained behaviour. `A` starts random, so the gradient for `B` is not zero and `B` begins to learn. Once `B` is non-zero, the gradient for `A` is non-zero too.

## How it works

For an input vector x, the adapted layer output is:

```python
h = W @ x + B @ (A @ x)   # frozen path + low-rank path
```

The training procedure is:

1. Freeze `W`, so no gradients are computed or stored for it.
2. Initialize `A` with small random values and `B` with zeros.
3. Run the forward pass through both paths and add the results.
4. Run the backward pass. Gradients are computed only for `A` and `B`.
5. Update `A` and `B` with the optimizer.
6. When you deploy, merge the update into the base matrix with `W_new = W + B·A`. The merged layer has the same shape and costs the same at inference as the original.

The rank `r` sets how many directions the change can use. If the change you need really has rank 4, an adapter of rank 4 can represent it. A rank-1 adapter cannot.
