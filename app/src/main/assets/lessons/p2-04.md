# Building an evaluation set

## The idea

Without an evaluation set, you judge a model by whether a few answers look good, and that judgment changes with your mood. An evaluation set is a fixed list of questions with reference answers. It is kept apart from everything the model or its retriever was built from. You run the same set after every change and compare the scores.

Worked example. An evaluation set has 20 questions. Under exact match, a retrieval change lifts the score from 11 correct answers to 13. That is 55 percent against 65 percent, a gain of 10 points. But it is only two questions. One answer flipping either way could explain it, so a small set can mislead you. Add questions before you trust a change of this size.

## How it works

1. Write questions that your real users would ask, drawn from your own documents. Include a few that the documents cannot answer, so that you can test whether the model admits it.
2. For each question, write a reference answer that is short and specific.
3. Keep the set in its own file, separate from the training data and the retrieval chunks. Hold back part of it as a test split, and do not tune prompts against that part.
4. Choose a scoring rule for each question. Exact match, after normalizing case, spaces and punctuation, suits short factual answers. For longer answers, use a graded rubric. A person, or a checklist of required facts, marks each answer 0, 1 or 2.
5. Run the model on every question, score the answers, and save the score together with the settings used.
6. Read every miss. Sort each one into a retrieval failure, a generation failure or a bad reference answer.

Exact match is strict. A correct paraphrase of a long answer scores zero, so use graded scoring for those questions.

## Steps

1. Open a Colab notebook or a laptop folder where you keep the documents and the model code.
2. Write 20 question and answer pairs in a file called `eval.jsonl`, one JSON object per line, with the keys `question` and `answer`.
3. Mark five of the pairs as your test split, and do not use them when you tune the prompt or the chunking.
4. Define `ask_model(question)` using the generation code from the earlier lessons.
5. Run the scoring script above. Save the printed score.
6. Change one thing, such as the chunk size or the number of retrieved chunks, and run the set again. Compare the two scores and read the new misses.

Step 5 uses this scoring script. The function `ask_model(question)` is a placeholder for the generation code from the earlier lessons.

```python
import json
import re

def normalize(s):
    s = s.lower().strip()
    return re.sub(r"[^a-z0-9 ]", "", s)

def exact_match(pred, gold):
    return normalize(pred) == normalize(gold)

rows = [json.loads(line) for line in open("eval.jsonl")]
hits = 0
for row in rows:
    pred = ask_model(row["question"])  # your function
    ok = exact_match(pred, row["answer"])
    hits += ok
    if not ok:
        print("MISS:", row["question"], "->", pred)
print(f"{hits}/{len(rows)} exact matches")
```

Library APIs change over time, so check the current documentation for any library call you add to `ask_model`.
