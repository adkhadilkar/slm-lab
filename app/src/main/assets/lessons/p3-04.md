# Running a model on your phone

## The idea

A phone does not run the training stack. Training uses PyTorch on a GPU. On a phone you want one file that holds the quantized weights, the tokenizer and the configuration, and a runtime written for CPU and phone hardware. GGUF is one such single-file format. The llama.cpp project provides tools that convert a model into GGUF, quantize it, and run it.

Worked example of file size. A model with 1 billion parameters stored at 4 bits per weight holds 1e9 x 4 / 8 = 5e8 bytes, which is about 0.5 GB. At 16 bits the same model would be 2 GB. A real file is somewhat larger, because of metadata and because some tensors may be kept at higher precision. On the phone, the file size is not the whole story. The runtime also needs working memory, so the model must fit in the memory the phone can spare.

## How it works

1. Start from a model directory saved by `transformers`. This can be a base model or a fine-tuned model with its adapter merged in.
2. Convert the directory to GGUF with the conversion script in the llama.cpp repository.
3. Quantize the GGUF file to a low-bit type. Choose the type from the tool's current list.
4. Run the file on a laptop with the same tool first. A wrong chat template or a poor quantization shows up there, where it is easier to debug.
5. Copy the file to the phone and open it with an on-device runtime that reads GGUF.
6. Check that the prompt format matches the chat template you used in the earlier lessons. The runtime must wrap messages the way the model expects.

The tools and their flags change over time. For the exact commands, see the current README of the tool you use. Do not copy command lines from an old tutorial.

## Steps

1. On a Colab or laptop session, make sure the model directory is saved and that you know its parameter count.
2. Clone the llama.cpp repository and follow its README to build the tools.
3. Run the conversion script on your model directory, producing a GGUF file. See the tool's current README for the exact command.
4. Quantize the GGUF file to a 4-bit type using the quantize tool. See the tool's current README for the exact command.
5. Estimate the size of the result with the code below and compare it with the file on disk.
6. Run one prompt on the laptop, then copy the file to the phone and run the same prompt there.

```python
import os

def estimate_gb(n_params, bits_per_weight):
    return n_params * bits_per_weight / 8 / 1e9

print(f"4-bit, 1B: {estimate_gb(1e9, 4):.2f} GB")

path = "model-q4.gguf"  # your converted file
if os.path.exists(path):
    print(f"file: {os.path.getsize(path) / 1e9:.2f} GB")
```

The tool names, options and file layouts change over time, so check the current llama.cpp documentation before you follow these steps.
